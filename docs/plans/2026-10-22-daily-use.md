# Plan: from a working skill to a daily tool

Status: decided 2026-10-22, not started. Build from this file; it holds every decision.

## Where we stand

- `main` and `stable` are at `2d138aa`. The Windows fix (`ddcacc1`) is on `claude/motion-graphics-premiere-skill-gtiyfh`, not merged.
- Nobody has done a real job with it yet. Premiere import (alpha edges, color, length) is unverified.
- Measured in a 4-core Linux sandbox: one 6 s lower third renders in 24.6 s, a batch of three in 58 s, `check.mjs` takes 2.4 s.
- Brand colors survive the encode exactly: #041443, #336699, #ED7D31, #518FC4 and #FFFFFF decode back unchanged from both ProRes 4444 and 422 HQ (decoded with `accurate_rnd+full_chroma_int`).

| 11 | The panel talks to the renderer through files in `~/motion-graphics/queue/`, not HTTP. | A UXP panel cannot start a program with arguments, and on macOS it may not use `http://` (Adobe docs: `resources/recipes/external-process`, `resources/recipes/network`). Files need only the `localFileSystem` permission. |
| 12 | A small render service (`scripts/serve.mjs`) runs from login: a LaunchAgent on macOS, a Startup-folder entry on Windows. It runs `git pull --ff-only` on start, so it follows `stable` like the skill. | Something outside Premiere has to run Chromium and ffmpeg. |
| 13 | The panel renders at the active sequence's frame rate and frame size, read from Premiere. | Templates are timed in seconds and sized in `vmin`/`vw`/`vh` (`craft.md`), so one template serves every sequence and the frame rate always matches. |
| 14 | A re-render never overwrites the media file; it writes `_v<n+1>` and swaps the clip on the timeline. | Premiere caches media by path. |
| 15 | Each render writes a sidecar `<file>.mov.json` saying which template and text made it. | The panel needs it to show and edit a selected clip's text. |
| 16 | Render speed is measured on his Mac through `jobs.log` before any optimisation. Parallel frame rendering only if a 6 s clip takes over 15 s there. | His Apple Silicon Mac is likely faster than the sandbox. |
| 17 | The panel ships as a `.ccx` installed by double-click. UXP packages need no signature (Adobe docs: `plugins/distribution/package`). If the double-click install fails, the fallback is Developer Mode plus the UXP Developer Tool on Marvel's machine only, and the panel waits. | One forum report says an unsigned `.ccx` would not install; task 5 settles it. |

## Constraints for every task

- Commit messages, PR titles and descriptions name no AI assistant; titles follow Conventional Commits (`commits` check).
- Work lands on `main` through squash-merged PRs; `stable` moves only by `scripts/promote.sh` or an equivalent fast-forward after `npm test` and `scripts/check-starters.sh` pass.
- `npm test` and `bash scripts/check-starters.sh` stay green on every PR.
- Client brand kits and templates never enter the repo.
- Time in seconds, sizes relative to the viewport (`craft.md`); nothing may assume 25 fps or 1920x1080.
- The editor never runs a command himself. Claude Code or the installer does.

## Interfaces

These are produced by one task and read by another. Names and fields are fixed here.

```
~/motion-graphics/
  brands/brand-<slug>.json            (exists, decision in PR #4)
  templates/<client>/<type>/          task 3 writes, tasks 6-7 read
    clip.html  fonts/  assets/
    template.json                     {"client": "productowner", "type": "lower-third",
                                       "fields": {"name": "Jan de Vries", "role": "Product owner"},
                                       "saved": "2026-10-22T14:03:00Z"}
  queue/                              task 7 writes jobs, task 6 writes results
    <id>.job.json                     {"template": "productowner/lower-third",
                                       "data": {"name": "...", "role": "..."},
                                       "fps": 25, "width": 1920, "height": 1080,
                                       "out": "<absolute path>.mov"}
    <id>.done.json                    {"out": "<absolute path>.mov"}
    <id>.error.json                   {"message": "<one sentence for the editor>"}
  jobs.log                            task 2: one tab-separated line per job:
                                       date  client  type  minutes  messages  renders  premiere-issues
<render>.mov.json                     task 3 writes next to every .mov:
                                       {"template": "productowner/lower-third", "data": {...}, "version": 1}
```

## Tasks

### Phase 1: real use now

**Task 1. Merge the Windows fix.**
Open a PR from `claude/motion-graphics-premiere-skill-gtiyfh` (`ddcacc1`), merge after `commits` is green, then promote.
Run: `npm test && bash scripts/check-starters.sh`
Expected: `# pass 21`, `# fail 0`, 14 lines starting with `ok`.

**Task 2. Job log.**
`SKILL-BODY.md`: at intake, write the start time to `$J/started`; after the final, append one line to `~/motion-graphics/jobs.log` in the format above (minutes from `$J/started`, messages counted from the conversation, renders = final renders including re-renders, Premiere issues as he reports them or `-`). Docs only, no test.
Check: a dry-run job in Claude Code leaves one line in `jobs.log` with 7 tab-separated fields.

**Task 3. Templates and sidecars.**
- `scripts/save-template.mjs <job-dir> <client> <type> [--replace]` copies `clip.html`, `fonts/`, `assets/` to `~/motion-graphics/templates/<client>/<type>/` (root overridable with `MG_TEMPLATES` for tests) and writes `template.json` with the clip's `defaults` as `fields`. Without `--replace` it refuses an existing template and says so in one line.
- `scripts/render.mjs` writes `<out>.json` next to every `.mov` it renders (not previews or stills), with the template name when the clip came from a template, else `null`, and the data row used.
- `SKILL-BODY.md` section 5: after sending the final, run `save-template.mjs`; ask before replacing.
Tests first in `test/template.test.mjs` and `test/render.test.mjs`:
  - save-template copies a job and writes `template.json` whose `fields` equal the clip's defaults;
  - save-template refuses an existing template without `--replace` and exits 1;
  - a batch render writes one sidecar per `.mov`, each with its own row.
Run: `npm test`
Expected: `# fail 0`, three more passing tests than before.

**Task 4. Install and first jobs.**
README: an "Install" section with the Claude Code prompts for Mac and Windows (from the conversation of 2026-10-08), now also creating `~/motion-graphics/templates/` and `queue/`. Promote. The editor installs and does real jobs; Marvel sets a week-4 review date.
Check (in Premiere, by the editor): the `.mov` sits over footage with a transparent background, edges at 400% show no dark or light fringe, Lumetri's eyedropper reads the brand hex on a flat area, and the clip is exactly the expected number of frames.

### Phase 2: the panel (Marvel's Windows Premiere first)

**Task 5. Spike: can a panel do the three Premiere moves?** Timebox: one day.
`panel/manifest.json` (manifest v5, host `premierepro` min 25.6, `localFileSystem: "fullAccess"`), `panel/index.html`, `panel/main.js` with three buttons:
  1. show the media path of the selected timeline clip (`Sequence.getSelection` → `VideoClipTrackItem.getProjectItem` → `ClipProjectItem.getMediaFilePath`);
  2. import a fixed `.mov` (`Project.importFiles`);
  3. place it at the playhead on the top video track (`Sequence.getPlayerPosition`, `SequenceEditor.createOverwriteItemAction`).
`scripts/package-panel.sh` → `out/motion-graphics-panel.ccx`.
Check on Marvel's Windows Premiere: the `.ccx` installs by double-click, the panel opens from Window > UXP Plugins, and all three buttons work.
Gate: all three work → task 6. The install fails → decision 17's fallback, report before going on. A move is missing from the API → stop and re-plan; do not build around it.

**Task 6. Render service.**
`scripts/serve.mjs <queue-dir>` picks up `*.job.json` one at a time, runs `check.mjs` on the template with the job's data, size and fps, renders with `render.mjs`, and writes `.done.json` or `.error.json` (the check's FAIL line turned into one sentence). `scripts/install-service.sh` writes the LaunchAgent (macOS) or the Startup entry (Windows) and starts it.
`lib/mg.js` / `scripts/page.mjs`: accept a size and fps override from the job, so `MG.clip` uses the sequence's values.
Tests first in `test/serve.test.mjs`:
  - a job for a template in a temp dir yields a `.mov` with the job's fps and size, plus `.done.json`;
  - a job whose text is too long for title-safe yields `.error.json` that names the field, and no `.mov`;
  - two jobs dropped at once both finish, one after the other.
Run: `npm test`
Expected: `# fail 0`.

**Task 7. Panel v1.**
- New clip: pick a template (folders under `templates/`), fill its `fields`, Render. The panel writes a job with the active sequence's fps and size, waits for the result, imports it into a bin named `Motion graphics`, and places it at the playhead on the top video track.
- Edit: with a clip selected, the panel reads its sidecar and shows the fields filled in; Render writes `_v<n+1>`, imports it, and overwrites the selected clip at the same start and track.
- Every wait shows progress; a missing service, a missing sidecar or an `.error.json` shows one sentence.
UXP panels have no test runner in this repo. Manual checklist in `panel/CHECKLIST.md`, run on Marvel's Windows Premiere and then the editor's Mac:
  new clip at 25 and 29.97 fps sequences; edit a selected clip twice (v2, v3); select a clip the tool didn't make; stop the service and press Render; a name too long for the design.
Then the editor installs the `.ccx`.

**Task 8. Speed, only if needed.**
If `jobs.log` or the panel shows a 6 s clip taking over 15 s on the editor's Mac: render frames in parallel pages in `render.mjs`. Test first: a parallel render's frames hash identically to a serial render's.

**Task 9. Week-4 review.**
Read `jobs.log` with the editor. Decide: delete the app path (decision 4), batch from a pasted list, duration changes, or something the log shows.

## What could break

- A name longer than the design allows. The service runs `check.mjs` first and returns the failing field (task 6 test).
- A clip on the timeline that the tool didn't make, or whose sidecar was moved. The panel says so and offers "new clip" instead (task 7 checklist).
- Two renders requested at once. The service works the queue one job at a time (task 6 test).
- The service is not running. The panel gives up after 15 s with one sentence telling him to restart it (task 7 checklist).
- A sequence at 23.976, 29.97 or 59.94, or vertical. The job carries the sequence's fps and size; `RATES` already holds the exact rationals (task 6 test covers a non-25 rate).
- Paths with spaces or non-ASCII names on Windows ("Jan de Vries", `C:\Users\Zoë\Videos`). The task 6 tests use such a path.
- A template saved from a job whose fonts were missing. `save-template.mjs` copies `fonts/`; `check.mjs` fails a clip whose font did not load, so the service catches it.
- Premiere shows a fringe on soft edges because it reads the alpha as premultiplied. Chromium writes straight alpha. Task 4's Premiere check catches it; the fix is in the encode, not in Premiere settings he has to remember.
